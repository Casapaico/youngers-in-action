01Cómo funcionará el sitio

La web deja de ser un archivo que solo toca el desarrollador. Vas a tener un panel privado donde editas texto y fotos como si fuera un formulario, y el sitio se actualiza solo.

paso 1

Entras a /admin

Inicias sesión con tu cuenta de GitHub (te la creamos y te agregamos al proyecto).

paso 2

Editas

Cambias una foto, escribes una novedad, agregas una fecha de reunión. Todo con campos claros en español.

paso 3

Guardas

Un botón «Publicar». No hay que subir archivos por FTP ni tocar código.

paso 4

Sale en vivo

En 1–2 minutos el cambio aparece en youngersinaction.org. Si algo sale mal, se revierte.

Sin costo

No se contrata AWS, ni servidor, ni base de datos. El panel corre sobre GitHub + Netlify, ambos en plan gratuito. El único requisito nuevo es que la coordinación tenga una cuenta de GitHub (gratis, se configura una sola vez).

03Guía de fotos

El panel comprime las imágenes automáticamente, pero conviene subirlas ya razonables. Regla simple: horizontal para fondos, cuadrada para personas, y nada por encima de ~1 MB.

Cómo dejar una foto lista en 1 minuto

Abrí squoosh.app o tinypng.com (gratis, sin instalar nada), arrastrá la foto, elegí el tamaño de la tabla y descargá. Formato JPG para fotos, PNG para logos.

Buenas prácticas

Luz natural, horizontal siempre que se pueda, dejá «aire» alrededor del sujeto (el sitio recorta según la pantalla). Evitá capturas de pantalla, fotos con fecha impresa y collages.

06Novedades y agenda: qué se necesita para cada una

Son las dos secciones nuevas y las que vas a alimentar más seguido. Los formularios del panel serán cortos.

Una novedad

CampoQué poner
TítuloConcreto, sin mayúsculas gritadas. «Cerramos el primer ciclo de EmpoderArLAS 2026».
FechaLa del hecho, no la de publicación.
Portada1 foto horizontal, 1200×800. Con permiso si hay menores.

08Plan de trabajo del lado técnico

Lo que hará el equipo de desarrollo mientras la ONG reúne los materiales. Cada fase termina con una revisión conjunta.

Fase 0

Preparación y dirección visual

Actualizar Astro, definir el «ADN de diseño» a partir de referencias de ONGs profesionales, fijar el presupuesto de performance.

Fase 1

Contenido editable

Sacar todos los textos y listas del código y ponerlos en un formato que el panel pueda editar. Una sola fuente para las cifras y las redes.

Fase 2

Panel /admin

Instalar Sveltia CMS, configurar el acceso con GitHub, onboarding de la coordinación con una prueba real.

Fase 3

Novedades + Agenda

Crear las dos secciones nuevas, sus páginas públicas y sus formularios en el panel.

Fase 4

Rediseño y performance

El minijuego sigue cargando al inicio; el resto pasa a presentación con scroll dinámico, imágenes optimizadas y accesibilidad AA.

Fase 5

Esta carpeta, versión final

Con capturas del panel ya funcionando y la plantilla de consentimiento validada.

Lo que se necesita de la ONG para no frenar

Antes de Fase 2: la cuenta de GitHub de quien vaya a administrar. Antes de Fase 3: las 2–3 novedades y las fechas iniciales. Antes de Fase 4: la foto principal de portada en buena calidad.
